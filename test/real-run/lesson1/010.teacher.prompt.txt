You write a lesson on ONE knowledge point of Python in Learning Companion, from a plan by a planning AI.
Point: "What a model learns: features, target and parameters".
Subject: Python
Learner's goal: Use Python for machine learning: load and clean data, train models with scikit-learn, and understand what the code does.
Points the learner has marked as learned: none.

The plan:
Aim: Describe a model as a function that maps input features to a target through parameters fitted from example data, and point to the features, the target and the fitted parameters in a simple scikit-learn LinearRegression fit.
Approach: Start from something the learner already knows, a hand-written Python function with fixed numbers in it, and let the one real question appear: where do those numbers come from when nobody knows them? Then make the learner score three candidate sets of numbers by hand, so 'fitting' becomes 'choosing the numbers with the smallest error on the examples', and only then show scikit-learn doing the same job and reproduce its answer with a few lines of plain Python. The smallest possible case (one feature, a straight line, four rows) is used because every number can be checked by eye, and the aim is that model.fit(X, y) stops being a black box.
1. A function with numbers you have to know. Teach: Open with a plain Python function the learner can read: def predict(size, w, b): return w * size + b, so price = w × size + b. Say what a function does here (takes an input, returns an output) in one sentence, in case the learner is new to def. Then pose the problem: if you write w = 2 and b = 50 yourself, you are guessing. A model is exactly this kind of function, with the difference that the numbers w and b are not typed in by a person but worked out from examples of houses whose price is already known. Name the three parts as a small table: feature (the input the function receives: floor area in m²), target (the output we want it to produce: price in thousands), parameters (the numbers inside the function that are fitted: w and b). Mention that with several features the function simply has one weight per feature, e.g. price = w1 × size + w2 × rooms + b, with the same idea. Also name hyperparameters in one sentence (settings a person chooses before fitting, e.g. whether to include b) and say they are a different thing from parameters; they come back in a later topic. Example: Show the data as two lists, sizes = [50, 70, 90, 110] and prices = [160, 210, 270, 310], and the predict function. Print predict(80, 2, 50) which gives 210, and note that nothing says 2 and 50 are right. No fitting yet; the example only sets up the vocabulary and the question.
2. Fitting is choosing parameters that make the error small. Teach: Define the error of one prediction as predicted minus actual, and the mean squared error as the average of the squares of those errors (squaring so over- and under-predictions do not cancel and big misses count more). Explain that 'fitting' or 'training' means: among all possible (w, b), find the pair with the smallest error on the example data. The learner should see this by trying candidates, not take it on trust. Briefly explain zip (walks two lists in step) and the list comprehension where they appear. Example: Program: sizes and prices as above; predict(size, w, b); mean_squared_error(w, b) built with errors = [predict(s, w, b) - p for s, p in zip(sizes, prices)] and sum(e * e for e in errors) / len(errors); then loop over the pairs (2, 50), (3, 0), (2.55, 33.5) and print f"w={w}, b={b}: mean squared error = {round(mean_squared_error(w, b), 2)}". Exact output: 'w=2, b=50: mean squared error = 925.0', 'w=3, b=0: mean squared error = 125.0', 'w=2.55, b=33.5: mean squared error = 17.5'. Point out that the third pair is not magic: it is the pair the next section gets from scikit-learn, and no pair of numbers does better on these four rows.
3. Letting scikit-learn do the fitting. Teach: Show the same job with LinearRegression. Explain line by line: X is the table of features with one row per example and one column per feature, which is why a single feature still goes in as [[50], [70], ...] (a list of rows); y is the list of targets; model = LinearRegression() creates the function with no parameters chosen yet; model.fit(X, y) is the fitting step, which sets the parameters; model.coef_ holds the weight(s), one per feature, and model.intercept_ holds b; the trailing underscore is scikit-learn's convention for 'a value that exists only after fit' (stated in its glossary; the learner can check there). Show model.predict taking features only, never the target: at prediction time the target is exactly what we do not know. Say that X and y get their own lesson right after this one, so the learner only needs the picture here. Keep printed values wrapped in round(float(...), 2) so the output is exact and free of floating-point noise. Example: Program: from sklearn.linear_model import LinearRegression; X = [[50], [70], [90], [110]]; y = [160, 210, 270, 310]; model = LinearRegression(); model.fit(X, y); print(round(float(model.coef_[0]), 2)); print(round(float(model.intercept_), 2)); print(round(float(model.predict([[80]])[0]), 2)). Exact output: 2.55, then 33.5, then 237.5. Tie back: the numbers equal the best pair from the previous example, and 2.55 × 80 + 33.5 = 237.5, so predict for a new house of 80 m² is just the formula with the fitted numbers.
4. The surprise: after fitting, the model is only numbers. Teach: Show what fitting really produced. Rebuild the prediction with the earlier hand-written predict function, feeding it model.coef_[0] and model.intercept_, and show that it gives the same answer as model.predict. Conclusion the learner should be able to say in their own words: the examples are used once, to choose the parameters, and are not looked up again when predicting; what the model 'learned' is w and b. Then show that the same code on different data gives a different function: change the targets to [110, 150, 190, 230] (which follow price = 2 × size + 10) and fit again; the parameters change to 2.0 and 10.0 while not one line of the model code changed. This is the sense in which the function is 'fitted from data rather than written by hand'. Be honest about scope: this picture (a small fixed set of numbers that replaces the data) is exact for linear regression; some models work differently, e.g. k-nearest neighbours keeps the training rows and looks them up at prediction time, and a decision tree stores split thresholds rather than weights, so 'parameters' is looser there. Mention that these are met later. Example: Program continuing the previous one: w = model.coef_[0]; b = model.intercept_; print(round(float(predict(100, w, b)), 2)); print(round(float(model.predict([[100]])[0]), 2)); then model2 = LinearRegression().fit(X, [110, 150, 190, 230]) (explain that fit returns the model itself, so this one-liner works); print(round(float(model2.coef_[0]), 2), round(float(model2.intercept_), 2)). Exact output: 288.5, 288.5, then '2.0 10.0'.
5. Where 2.55 and 33.5 actually come from. Teach: Make 'fitting' something the learner could rebuild. For one feature and a straight line, the pair with the smallest mean squared error has a closed form: slope w = Σ(x − x̄)(y − ȳ) / Σ(x − x̄)², intercept b = ȳ − w × x̄, where x̄ and ȳ are the averages. Explain in words: the slope measures how much x and y move together, relative to how much x moves on its own, and the intercept makes the line pass through the point of averages. Walk the arithmetic for the example: x̄ = 80, ȳ = 237.5, Σ(x − x̄)(y − ȳ) = 5100, Σ(x − x̄)² = 2000, so w = 5100 / 2000 = 2.55 and b = 237.5 − 2.55 × 80 = 33.5. Say plainly that this exact formula exists for straight-line least squares only; other models find parameters by searching step by step (see beyond). Example: Program: mx = sum(sizes) / len(sizes); my = sum(prices) / len(prices); sxy = sum((s - mx) * (p - my) for s, p in zip(sizes, prices)); sxx = sum((s - mx) ** 2 for s in sizes); w = sxy / sxx; b = my - w * mx; print(sxy, sxx, w, round(b, 2)). Exact output: '5100.0 2000.0 2.55 33.5'. Then print the four residuals (predicted minus actual) as -1, -2, 7, -4 using the rounded fitted line and note they are not zero: the line does not hit every point, and it is still the best straight line for these rows.
Beyond this lesson: Worth knowing, with the first two deserving a proper extension after the lesson. (1) How fit finds the parameters when no neat formula exists: most models start from a guess and repeatedly nudge the parameters in the direction that lowers the error (gradient descent is the best-known version), while linear regression can be solved directly by least squares; I believe scikit-learn's LinearRegression does this with a linear-algebra routine from SciPy (scipy.linalg.lstsq) but I am not fully certain of the exact routine in every version, so the learner can check the source or the User Guide page on Linear Models. The learner can observe the effect by printing model.coef_ and model.intercept_ after every fit and changing one thing in the data at a time. (2) What 'parameter' means and where the idea stops being tidy: parameters are fitted, hyperparameters are chosen by the person (the boundary is clear in LinearRegression and blurrier for models such as nearest neighbours or trees); inspecting any fitted scikit-learn object with vars(model) or dir(model) shows the attributes ending in an underscore that fit created, which the learner can use as a habit with every later model. (3) A thing the lesson does not claim: a small error on the rows used for fitting does not by itself show the model learned something useful, for example a straight line through only two rows always has zero error; this is the subject of the training and test sets and overfitting lessons, so only a pointer is needed, not an extension here.
Link to the learner's goal: Every scikit-learn model you train follows this shape: you pass features X and a target y to model.fit(X, y), it sets fitted parameters you can read from attributes such as coef_ and intercept_, and model.predict(X_new) uses only those parameters.

- Surprises. A surprising case is worth showing when explaining it reveals how Python works underneath, as in a = [1, 2]; b = a; b.append(3); print(a) prints [1, 2, 3], even though the code never touched a. Assignment in Python never copies anything. It makes a name refer to an object, so a and b are two names for the same list, and changing the list through one name shows through the other. The same rule explains why a function can change a list you pass to it, and why a pandas DataFrame or NumPy slice you 'copied' with = changes the original.. A mistake that reveals nothing, such as a slip (Forgetting the colon after an if or for line, typing pirnt instead of print, a missing closing parenthesis, writing from sklearn.linear_model import LinearRegresion, or misspelling a column name like df['prcie'].) or a wrong idea no reasonable learner holds, teaches nothing, so leave it out. Don't claim how common a mistake is: there is no data on that.
